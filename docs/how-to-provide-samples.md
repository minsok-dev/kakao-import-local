# 샘플 파일 두는 방법 (에이전트·개발 공용)

<!-- [변경사유]: 운영자가 샘플을 어디에 두면 확인 가능한지 안내 -->

## 권장: 두 갈래

| 종류 | 경로 | git | 에이전트 확인 |
|------|------|-----|----------------|
| **원본(실명·실대화)** | `input/raw/` | ❌ gitignore | ✅ 디스크에만 있으면 Read 가능. **채팅에 붙여넣지 말 것** |
| **마스킹 샘플(공유용)** | `fixtures/samples/<시나리오ID>/` | ✅ 가능 | ✅ 우선 검토 대상 |
| **정답 JSON** | `fixtures/golden/<시나리오ID>.json` | ✅ | ✅ |

`input/` 은 `.gitignore` 대상이라 커밋되지 않지만, 워크스페이스 안이면 **파일 읽기로 확인 가능**합니다.

## 폴더 예시

```text
kakao-import-local/
  input/raw/                 ← 원본 (gitignore)
    room-salsa/
      KakaoTalk_Chat_....txt
      photos/
        001.jpg
  fixtures/
    samples/                 ← 마스킹본 (커밋 가능)
      S02_photo_one/
        README.md            ← 한 줄 설명
        export.txt           ← 마스킹된 대화
        photos/
          001.jpg            ← 더미/모자이크/무관한 테스트 이미지여도 됨
      S03_photos_multi/
        ...
    golden/
      S02_photo_one.json     ← image → message 정답
```

## 제가 확인하려면

1. 위 경로에 파일을 두고  
2. 채팅에 예:  
   `fixtures/samples/S02_photo_one/ 확인해줘`  
   또는  
   `input/raw/room-salsa/ 구조만 보고 파서 포인트 짚어줘`  

이미지(jpg/png)도 워크스페이스에 있으면 열어볼 수 있습니다.  
다만 **실명·전화번호가 보이는 원본**은 `input/raw/`에만 두고, 가능하면 마스킹본을 `fixtures/samples/`에 추가로 주세요.

## 최소로 주시면 되는 것

시나리오 하나라도:

1. `export.txt` (또는 카카오 내보내기 원본 파일명 그대로)  
2. `photos/` 안 이미지 1장 이상  
3. (가능하면) `fixtures/golden/….json` 또는 메모:

```text
001.jpg → 메시지 (오전 10:12 근처 / “포스터 올립니다” 다음)
```

정답 JSON이 없어도, txt + 사진 + “이 사진에 붙는 말” 메모만 있으면 확인을 시작할 수 있습니다.

## 운영 레이아웃 변형: 이미지 공용 폴더 + 방별 대화

효율(중복 이미지 1회 보관)을 위해 아래도 **1급 입력**으로 본다.

```text
input/raw/
  photos/                 ← 모든 방 이미지 공용 (SHA exact에 유리)
  chats/
    room-a.txt            ← 방별 대화만
    room-b.txt
```

또는 `input/raw/*.txt` + `input/raw/photos/`.

### 이 레이아웃의 이슈 (2026-07-24 샘플 확인)

**배치 확인 (재배치 후):**

```text
input/raw/
  chats/   ← group txt 7개 ✅
  photos/  ← 660장 ✅
```

대화 형식(PC 내보내기):

```text
{방제목} 님과 카카오톡 대화
저장한 날짜 : YYYY-MM-DD ...
--------------- YYYY년 M월 D일 요일 ---------------
[닉네임] [오전/오후 H:MM] 본문
[닉네임] [오전/오후 H:MM] 사진
[닉네임] [오전/오후 H:MM] 사진 N장
[닉네임] [오전/오후 H:MM] 동영상 | 이모티콘 | 파일: ...
```

**실측 (7개 txt 합산, 대략):**

| 항목 | 값 |
|------|-----|
| 본문에 `KakaoTalk_` 파일명 출현 | **0** |
| `] 사진` (1장) | ~19,037 |
| `] 사진 N장` | ~6,044 |
| 메시지 기준 이미지 슬롯(1+N 합) | **~46,660** |
| `photos/` 실제 파일 | **660** |
| `] 동영상` / `이모티콘` / `파일:` | 수천 (매칭 대상 아님·별도) |

→ 대화에 나온 사진의 **대부분 로컬 파일 없음**(일부만 다운로드한 상태).  
→ **파일명 직접 링크 불가**. 시각·순서·인접 텍스트 휴리스틱 + ambiguous/review가 기본.

| 이슈 | 설명 |
|------|------|
| 경로로 방 귀속 불가 | 사진이 어느 방 것인지 폴더로 알 수 없음 → **대화 매칭에 전적으로 의존** |
| 파일명↔메시지 링크 없음 | export에 `KakaoTalk_….jpg` **문자열은 미포함** (실측 0건). 다만 파일명에 **시각이 인코딩**되어 메시지 시각과 매칭 가능 — [golden-esencia-20260724-0050.md](./golden-esencia-20260724-0050.md) |
| 파일명 시각 ≠ 전송 시각 | `KakaoTalk_YYYYMMDD_HHMMSSmmm` 은 **저장/다운로드 시각**일 수 있음 |
| 슬롯 ≫ 파일 | 메시지 사진 슬롯 ~4.6만 vs 파일 660 → 대다수 `[사진]`은 unmatched(파일 없음) |
| 교차 방 오매칭 | 공용 풀 + 시각만으로 여러 방 메시지에 후보 → ambiguous/review |
| 다대다 | 동일 SHA 1파일 ↔ 여러 방 메시지 |
| 비표준 파일명 | uuid·해시형 소수 → 시각 휴리스틱 불가 |
| 오탐 | 본문 중 “얼굴사진” 등은 첨부가 아님 → `] 사진` / `] 사진 N장`만 첨부 마커로 취급 |

스캐너 설계: `photos_root`(공용) + `chats/*.txt`(방별) 분리. 방 폴더 안에 사진이 있다는 가정은 **폐기**.
